# Cloud-only Docker: independent build optimization for Python XiaoZhi

This PR is based **directly on main**. It can be reviewed and merged
independently of PR #1 (MiMo cloud models) and PR #2 (Jellyfin MCP playback).

The normal `Dockerfile-server`, `Dockerfile-server-base`,
`requirements.txt` and upstream Compose deployments stay unchanged.

## Scope

The Cloud-only image keeps Python WebSocket/HTTP services, MCP client,
OpenAI-compatible remote LLM/ASR/TTS providers, FFmpeg, Opus and the **small
local Silero ONNX VAD** (CPU `onnxruntime`).

It intentionally does not install PyTorch, torchaudio, FunASR, ModelScope,
Transformers, Sherpa ONNX, Vosk, mem0ai or other unused local model stacks.
The Python Silero VAD implementation uses ONNX directly and does **not**
require the `silero_vad` PyTorch package.

The optional `get_news_from_newsnow` plugin requires MarkItDown and is
disabled only in this image by the environment setting
`XIAOZHI_DISABLED_PLUGINS=get_news_from_newsnow`. The ordinary upstream
plugin loading behavior is unchanged.

The image can be built on `main` today; when MiMo PR #1 and Jellyfin PR #2
are later merged, rebuilding this image **automatically includes their code**.
Its smoke test checks MiMo providers only when they exist and never
requires Jellyfin in order to build.

## 1. Configure

From the repository root:

```bash
mkdir -p main/xiaozhi-server/data
cp main/xiaozhi-server/config.cloud.example.yaml main/xiaozhi-server/data/.config.yaml
cp .env.cloud.example .env.cloud
```

Replace the placeholder credentials and `YOUR_LAN_IP`. The base example uses
remote OpenAI ASR/TTS and OpenAI-compatible Qwen LLM; all adapters exist in
`main`. To use another compatible vendor, change the corresponding API
endpoint and model ID.

**For MiMo:** once PR #1 has been merged into `main`, use
`main/xiaozhi-server/config.cloud.mimo.example.yaml` in place of the base
example. It configures MiMo ASR, MiMo LLM and MiMo TTS.

If you already have `data/.config.yaml`, **do not overwrite it**.

## 2. Build a local image

```bash
DOCKER_BUILDKIT=1 docker compose --env-file .env.cloud -f compose.cloud.yml build xiaozhi-server
docker compose --env-file .env.cloud -f compose.cloud.yml up -d --no-build xiaozhi-server
docker compose --env-file .env.cloud -f compose.cloud.yml logs -f xiaozhi-server
```

Image creation installs the cloud dependencies in a cached stage; Python
source changes reuse that stage. `Dockerfile.cloud.dockerignore` excludes
unneeded model data and local files while retaining the 2.3 MB ONNX VAD model.

The Docker build runs `pip check` and
`python scripts/cloud_smoke_test.py`, which imports the app and included
plugins, loads the CPU ONNX model and rejects accidentally reinstalled
heavy local-model dependencies. Missing imports cause the build to fail.

After a source-only edit:

```bash
DOCKER_BUILDKIT=1 docker compose --env-file .env.cloud -f compose.cloud.yml build xiaozhi-server
docker compose --env-file .env.cloud -f compose.cloud.yml up -d --no-deps xiaozhi-server
```

## 3. Jellyfin MCP (after PR #2)

When PR #2 has merged, configure the separate Jellyfin MCP extension at
`z7ping/jellyfin-mcp@feature/mcp-audio-stream`.
Add `main/xiaozhi-server/data/.mcp_server_settings.json`:

```json
{
  "mcpServers": {
    "jellyfin": {
      "url": "http://YOUR_MCP_SERVER:8080/mcp",
      "transport": "streamable-http",
      "headers": {"Authorization": "Bearer YOUR_MCP_TOKEN"}
    }
  }
}
```

Set `MCP_MEDIA_ALLOWED_HOSTS` in `.env.cloud` to the hostname of the
`--audio-public-url` generated by that MCP server, not the Jellyfin REST
hostname. The Python container must be able to reach both the MCP endpoint
and the temporary `/audio/` links. Only the Jellyfin MCP service needs the
Jellyfin API Key.

Before PR #2 merges, the main-branch image supports regular MCP calls but
does **not** include the Jellyfin-to-ESP32 audio playback extension.

## 4. Optional Java/Vue administration console

Standalone configuration requires only the Python service; MySQL, Redis
and the Java manager are **not required**.

If you want the full management console, the Compose `manager` profile
can build and start the Java/Vue manager, MySQL and Redis:

```bash
docker compose --env-file .env.cloud -f compose.cloud.yml --profile manager build manager
docker compose --env-file .env.cloud -f compose.cloud.yml --profile manager up -d
```

Use the upstream `config_from_api.yaml` structure with
`manager-api.url=http://manager:8002/xiaozhi` and its actual API secret;
do not combine standalone and API-driven configuration. MiMo model
registration in the manager requires PR #1 to have merged.

**For development**, avoid rebuilding the manager for every Python change.
Rebuild only the `xiaozhi-server` service.

## 5. Acceptance and measurement

```bash
docker compose --env-file .env.cloud -f compose.cloud.yml exec xiaozhi-server python scripts/cloud_smoke_test.py
docker image ls xiaozhi-python-cloud
docker image inspect xiaozhi-python-cloud:dev --format='{{.Size}} bytes'
```

Use a real device to test cloud ASR, function/tool calling, remote LLM,
TTS, and VAD. When PRs #1/#2 merge, also test MiMo and Jellyfin single-track,
FLAC-transcoded-to-MP3 playback, playlists and interruptions.

There is **no measured image size or verified successful Docker build yet**;
the checks run when you build locally. The image does not preserve optional
provider SDKs that were explicitly excluded: use the full image, or explicitly
add required dependencies, when enabling them.
